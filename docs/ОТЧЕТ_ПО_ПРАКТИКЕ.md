## ВВЕДЕНИЕ

В современных условиях устойчивое функционирование жилищно-коммунального комплекса Российской Федерации неразрывно связано с внедрением отечественных цифровых технологий. Муниципальное водоснабжение и водоотведение представляют собой ключевые элементы жизнеобеспечения населения, промышленных и бюджетных организаций. Высокая интенсивность финансовых и материальных потоков в сфере ресурсоснабжения обуславливает повышенные требования к скорости, надежности и юридической достоверности учета абонентов, приборов учета холодной и горячей воды, расхода потребляемого ресурса и своевременности взаиморасчетов.

Производственная практика (по профилю специальности) выполнена в период с 20 октября 2026 г. по 09 ноября 2026 г. в обществе с ограниченной ответственностью «Водоканал-Сервис», расположенном по адресу: Красноярский край, г. Канск, мкр. 4-й Центральный, д. 33. Предприятие осуществляет централизованное водоснабжение и водоотведение жилищного фонда и объектов социально-бытовой инфраструктуры города Канска.

**Цель производственной практики** — закрепление и углубление теоретических знаний, полученных в ходе освоения профессиональных модулей ПМ.02 «Осуществление интеграции программных модулей» и ПМ.03 «Ревьюирование программных продуктов», приобретение практического опыта проектирования, разработки, тестирования, ревьюирования и экономического обоснования прикладного программного обеспечения в сфере биллинга коммунальных ресурсов.

Для достижения поставленной цели решены следующие **задачи:**
1. Изучить структуру предприятия ООО «Водоканал-Сервис», особенности организации бизнес-процессов абонентского и расчетно-кассового отделов, требования охраны труда и пожарной безопасности.
2. Провести предпроектное обследование и разработать формализованные функциональные модели (IDEF0, DFD), модели прецедентов (Use Case) и последовательности (Sequence).
3. Сформировать Техническое задание в соответствии с государственными стандартами (ГОСТ 34.602-89, ГОСТ 19.201-78).
4. Разработать концептуальную, логическую и физическую схемы базы данных, доказать нормализацию до третьей нормальной формы (3НФ), подготовить переносимые скрипты для SQLite и Microsoft SQL Server.
5. Создать программный комплекс десктопного типа на базе платформы .NET Framework 4.8.1 (C#, WPF) с реализацией архитектурного шаблона MVVM, строгим разграничением прав доступа четырех категорий пользователей (Администратор, Оператор абонентского отдела, Кассир, Абонент в личном кабинете), уникальным контрастным графическим интерфейсом и сервисом формирования квитанций.
6. Разработать и программно реализовать комплекс прикладных математических моделей (дифференцированное начисление платы, выявление аномального водопотребления, адаптивное прогнозирование спроса на ресурс).
7. Осуществить инспектирование, модульное (MSTest) и интеграционное тестирование программного кода, составить журнал разработки (Development Log) и оформить ревью исходных текстов.
8. Разработать матрицу рисков, SWOT-анализ, сетевой график PERT с расчетом критического пути, смету затрат на разработку и задел для выпускной квалификационной (курсовой) работы.

В процессе выполнения работы подтверждено освоение профессиональных компетенций ПК 2.1–ПК 2.5, ПК 3.1–ПК 3.4 и общих компетенций ОК 01–ОК 09.

## РАЗДЕЛ 1. ПМ.02 ОСУЩЕСТВЛЕНИЕ ИНТЕГРАЦИИ ПРОГРАММНЫХ МОДУЛЕЙ

### 1.1. МДК 02.01 Технология разработки программного обеспечения

#### 1.1.1. Изучение инструкции по технике безопасности и охраны труда

В первый день прохождения производственной практики на базе ООО «Водоканал-Сервис» студентом был пройден вводный и первичный инструктаж по охране труда, пожарной и электробезопасности под руководством инженера по охране труда предприятия. 

При работе с персональными электронно-вычислительными машинами (ПЭВМ) соблюдались требования СанПиН 1.2.3685-21 «Гигиенические нормативы и требования к обеспечению безопасности и (или) безвредности для человека факторов среды обитания» и инструкции предприятия:
- освещенность рабочего места на поверхности стола составляет не менее 400 лк;
- расстояние от глаз пользователя до экрана монитора выдерживается в диапазоне 600–700 мм, угол обзора по вертикали составляет 15–20 градусов ниже линии взгляда;
- каждые 50 минут непрерывной работы за компьютером организуется регламентированный перерыв продолжительностью 10 минут с выполнением гимнастики для глаз и разгрузочных физических упражнений;
- запрещается эксплуатация сетевых кабелей с видимыми повреждениями изоляции, включение оборудования со снятыми защитными крышками, загромождение путей эвакуации и вентиляционных решеток системных блоков.

В соответствии с требованиями программы практики, с использованием системы автоматизированного проектирования (САПР) разработан план эвакуации сотрудников расчетно-абонентского отдела ООО «Водоканал-Сервис» при возникновении чрезвычайной ситуации (пожара), представленный в Приложении А.

#### 1.1.2. Общая характеристика предприятия ООО «Водоканал-Сервис»

Общество с ограниченной ответственностью «Водоканал-Сервис» зарегистрировано и ведет непрерывную производственно-хозяйственную деятельность на территории муниципального образования город Канск Красноярского края.
- **Юридический и фактический адрес:** 663600, Красноярский край, г. Канск, мкр. 4-й Центральный, д. 33.
- **Организационно-правовая форма:** Общество с ограниченной ответственностью (ООО).
- **Сфера деятельности:** Забор, очистка и распределение воды для питьевых и промышленных нужд (ОКВЭД 36.00), сбор и обработка сточных вод (ОКВЭД 37.00), эксплуатация водопроводно-канализационного хозяйства, техническое обслуживание водомерных узлов, прием платежей от физических и юридических лиц.
- **Руководитель предприятия:** Генеральный директор ООО «Водоканал-Сервис».
- **Руководитель практики от предприятия:** Начальник абонентского отдела Уваркина Е.Г.

Организационная структура предприятия включает в себя:
1. Руководство (Генеральный директор, главный инженер);
2. Абонентский отдел (учет лицевых счетов, регистрация и опломбирование счетчиков, прием показаний, работа с должниками);
3. Касса / расчетный сектор (прием наличных и безналичных платежей, формирование фискальных квитанций, сверка выписок);
4. Аварийно-диспетчерская служба и ремонтно-эксплуатационный цех (устранение аварий, поверка приборов учета на выезде);
5. Отдел информационных технологий (сопровождение локальной вычислительной сети, серверов и рабочих станций).

Степень автоматизации до выполнения настоящего проекта характеризовалась фрагментарностью: часть абонентов фиксировалась в разрозненных электронных таблицах Excel, расчет начислений производился вручную с риском математических ошибок, кассиры не имели мгновенного доступа к текущей задолженности, а абоненты не имели возможности дистанционной передачи показаний счетчиков и печати квитанций. Это обусловило острую необходимость внедрения единой централизованной настольной информационной системы с возможностью автономной работы и перспективой перехода на корпоративный СУБД-сервер.

#### 1.1.3. Анализ бизнес-процессов абонентского отдела (IDEF0, DFD)

Для формализованного описания предметной области и выделения контуров автоматизации выполнено функциональное моделирование методологиями IDEF0 и DFD.

Контекстная диаграмма IDEF0 (A-0) «Учет абонентов и платежей водоканала» отображает функционирование системы:
- **Входы (Inputs):** Заявления граждан на подключение, паспорта приборов учета, текущие показания приборов учета воды, платежные средства (наличные/карты).
- **Выходы (Outputs):** Акты ввода счетчиков в эксплуатацию, платежные квитанции об оплате, сводные ведомости водопотребления, отчеты о задолженности, журнал аудита операций.
- **Управление (Controls):** Жилищный кодекс РФ, Постановление Правительства РФ № 354 «О предоставлении коммунальных услуг собственникам и пользователям помещений...», утвержденные тарифы Администрации г. Канска на водоснабжение и водоотведение, регламент безопасности персональных данных (ФЗ № 152-ФЗ).
- **Механизмы (Mechanisms):** Персонал (операторы, кассиры, администратор), персональные компьютеры, локальная вычислительная сеть, программный комплекс «VodokanalManager», СУБД SQLite / MS SQL Server.

Декомпозиция верхнего уровня (IDEF0 A0) разбивает процесс на 4 функциональных блока:
1. *Блок А1: Регистрация и сопровождение абонентов и счетчиков.* Включает ввод персональных данных, адреса, площади, количества проживающих, привязку счетчиков (ХВС/ГВС), ввод в эксплуатацию и поверку.
2. *Блок А2: Сбор показаний и расчет объема водопотребления.* Проверка монотонности показаний ($Curr \ge Prev$), расчет дельты расхода, выявление аномального всплеска.
3. *Блок А3: Тарификация и начисление платы.* Применение действующих тарифов Канского района, дифференцированный расчет сумм ХВС, ГВС и водоотведения, начисление пени при просрочке.
4. *Блок А4: Прием платежей и кассовые операции.* Внесение денежных средств, пересчет текущего сальдо лицевого счета, печать унифицированной квитанции.

Диаграмма потоков данных (DFD) детализирует движение информационных пакетов между внешними сущностями («Абонент», «Кассир», «Оператор»), процессами обработки («Валидация показаний», «Расчет суммы к оплате», «Фиксация платежа») и накопителями данных (хранилища D1 «Абоненты», D2 «Приборы учета», D3 «Показания», D4 «Платежи», D5 «Тарифы»).

### 1.3. МДК 02.03 Математическое моделирование в профессиональной деятельности

#### 1.3.1. Анализ предметных производственных задач для моделирования

В сфере коммунального водоснабжения и водоотведения ключевое значение имеют три взаимосвязанные прикладные математические задачи:
1. **Задача точного дифференцированного расчета стоимости услуг и штрафных санкций (пени):** Ошибки при начислении платы или округлении промежуточных сумм ведут к финансовым претензиям абонентов и судебным издержкам. Необходима строгая модель расчета по формулам Постановления Правительства РФ № 354.
2. **Задача оперативного обнаружения аномального водопотребления и утечек:** Неконтролируемый прорыв трубопровода в жилом помещении или скрытая поломка водосчетчика приводят к колоссальным перерасходам ресурса и конфликтам при оплате. Требуется алгоритм выявления статистических аномалий на этапе ввода показаний.
3. **Задача краткосрочного прогнозирования спроса на воду:** Оценка потребности жилого сектора в ресурсе необходима для оптимального регулирования давления в магистральных водоводах Канска и энергосбережения насосных станций 2-го подъема.

#### 1.3.2. Сбор данных и обоснование математических методов

Для математического моделирования использованы фактические обезличенные данные абонентского отдела ООО «Водоканал-Сервис» по жилому сектору 4-го Центрального микрорайона г. Канска за период с мая по октябрь 2026 года (выборка из 150 лицевых счетов с приборами учета типа СВК-15 и Бетар СГВ-15).

В качестве математического аппарата обоснованы:
- Метод линейных кусочно-заданных функций для начисления платы;
- Модель скользящего экспоненциального сглаживания и критерий относительного отклонения от индивидуального медианного профиля для детекции аномалий;
- Метод взвешенного скользящего среднего (Weighted Moving Average, WMA) для прогнозирования потребления воды на следующий расчетный период.

#### 1.3.3. Разработка математических моделей начислений, аномалий и прогнозирования

**1. Модель расчета начислений и пени:**
Сумма к оплате за расчетный месяц $S_{month}$ определяется выражением:
$$S_{month} = \sum_{i=1}^{k} (V_i \cdot T_i) + V_{отв} \cdot T_{отв} + P_{пени}$$
где $V_i = Curr_i - Prev_i$ — объем потребления по $i$-му счетчику (м³); $T_i$ — утвержденный тариф на соответствующую услугу (руб./м³); $V_{отв} = V_{ХВС} + V_{ГВС}$ — суммарный объем водоотведения; $T_{отв}$ — тариф на водоотведение; $P_{пени}$ — сумма пени, рассчитываемая при просрочке платежа свыше 31 дня в размере 1/300 ключевой ставки ЦБ РФ за каждый день просрочки.

**2. Модель детекции аномального расхода:**
Для абонента вычисляется базовый ожидаемый расход как среднее значение за последние $N$ месяцев ($N=3$):
$$\overline{V} = \frac{1}{N} \sum_{j=1}^{N} V_j$$
Относительное отклонение текущего расхода $V_{тек}$ от базового уровня:
$$\delta = \frac{V_{тек} - \overline{V}}{\overline{V}}$$
При выполнении условия $\delta > 0.30$ (превышение расхода более чем на 30% при минимальном пороге абсолютной дельты $V_{тек} - \overline{V} \ge 5\text{ м³}$) система фиксирует флаг `IsAnomaly = True` и выводит предупреждение о возможном порыве или неисправности счетного механизма.

**3. Модель прогнозирования водопотребления (WMA):**
Прогнозируемый расход на расчетный месяц $t+1$ определяется взвешенной суммой предыдущих фактических расходов с убывающими весами, отдающими приоритет наиболее свежим наблюдениям:
$$\hat{V}_{t+1} = \frac{\sum_{m=1}^{M} w_m \cdot V_{t-M+m}}{\sum_{m=1}^{M} w_m}$$
где $M=3$, весовые коэффициенты приняты $w_1 = 1$, $w_2 = 2$, $w_3 = 3$ (сумма весов $\sum w_m = 6$).

#### 1.3.4. Программная реализация моделей и оценка эффективности

## ПРИЛОЖЕНИЕ Б. Доказательство 3НФ реляционной схемы базы данных

Пусть реляционная схема базы данных биллинга включает отношение `Subscribers`:
`R = (AccountNo, FullName, Address, District, Area, ResidentsCount, CategoryId, UserId)`

1. **Первая нормальная форма (1НФ):**
   Все атрибуты являются скалярными (атомарными), отсутствуют повторяющиеся группы или списки в пределах одной кортежной записи. Следовательно, схема находится в 1НФ.

2. **Вторая нормальная форма (2НФ):**
   Первичным ключом отношения является `AccountNo`. Так как ключ простой (состоит из одного атрибута), любая неполная функциональная зависимость неключевого атрибута от части первичного ключа невозможна по определению:
   `AccountNo -> {FullName, Address, District, Area, ResidentsCount, CategoryId, UserId}`
   Следовательно, отношение находится во 2НФ.

3. **Третья нормальная форма (3НФ):**
   Все неключевые атрибуты функционально зависят непосредственно от первичного ключа и отсутствуют транзитивные зависимости между неключевыми атрибутами:
   - Справочник категорий льгот вынесен в отдельную таблицу `ServiceCatalogs (Id, Name, Rate)`;
   - Учетные записи аутентификации вынесены в отдельную таблицу `Users (Id, Login, PasswordHash, RoleId)`.
   В отношении `Subscribers` хранятся только внешние ключи `CategoryId` и `UserId`. Таким образом, в отношении отсутствуют транзитивные зависимости вида $X \rightarrow Y \rightarrow Z$, что строго доказывает соответствие схемы требованиям третьей нормальной формы (3НФ).

### Сложный запрос №1: Анализ задолженности абонентов и классификация платежной дисциплины
```sql
WITH PaymentAgg AS (
    SELECT 
        SubscriberId,
        COALESCE(SUM(Amount), 0.0) AS TotalPaid,
        MAX(PaymentDate) AS LastPaymentDate
    FROM Payments
    GROUP BY SubscriberId
),
ConsumptionAgg AS (
    SELECT 
        m.SubscriberId,
        COALESCE(SUM(mr.Consumption * t.Price), 0.0) AS TotalBilled
    FROM MeterReadings mr
    JOIN Meters m ON mr.MeterId = m.Id
    JOIN Tariffs t ON m.ServiceType = t.ServiceType AND t.IsActive = 1
    GROUP BY m.SubscriberId
)
SELECT 
    s.AccountNo,
    s.FullName,
    s.Address,
    s.District,
    COALESCE(ca.TotalBilled, 0.0) AS TotalAccrued,
    COALESCE(pa.TotalPaid, 0.0) AS TotalPaid,
    ROUND(COALESCE(ca.TotalBilled, 0.0) - COALESCE(pa.TotalPaid, 0.0), 2) AS CurrentDebt,
    pa.LastPaymentDate,
    CASE 
        WHEN (COALESCE(ca.TotalBilled, 0.0) - COALESCE(pa.TotalPaid, 0.0)) <= 0.0 THEN 'Переплата / Оплачено'
        WHEN (COALESCE(ca.TotalBilled, 0.0) - COALESCE(pa.TotalPaid, 0.0)) <= 1500.0 THEN 'Текущий долг (норма)'
        ELSE 'Злостный должник'
    END AS StatusCategory
FROM Subscribers s
LEFT JOIN ConsumptionAgg ca ON s.Id = ca.SubscriberId
LEFT JOIN PaymentAgg pa ON s.Id = pa.SubscriberId
ORDER BY CurrentDebt DESC;
```

### Сложный запрос №2: Помесячная динамика водопотребления по районам Канска с оконными функциями
```sql
WITH MonthlyDistrictConsumption AS (
    SELECT 
        s.District,
        SUBSTR(mr.ReadingDate, 1, 7) AS YearMonth,
        SUM(mr.Consumption) AS TotalVolume
    FROM MeterReadings mr
    JOIN Meters m ON mr.MeterId = m.Id
    JOIN Subscribers s ON m.SubscriberId = s.Id
    GROUP BY s.District, SUBSTR(mr.ReadingDate, 1, 7)
)
SELECT 
    District,
    YearMonth,
    TotalVolume,
    LAG(TotalVolume, 1, TotalVolume) OVER(
        PARTITION BY District 
        ORDER BY YearMonth
    ) AS PreviousMonthVolume,
    ROUND(TotalVolume - LAG(TotalVolume, 1, TotalVolume) OVER(
        PARTITION BY District 
        ORDER BY YearMonth
    ), 2) AS GrowthVolume,
    ROUND((TotalVolume * 100.0) / SUM(TotalVolume) OVER(
        PARTITION BY YearMonth
    ), 2) AS DistrictSharePercentage
FROM MonthlyDistrictConsumption
ORDER BY YearMonth DESC, TotalVolume DESC;
```

### Листинг 2 — Доменные правила и математические модели (`DomainRules.cs`)
```csharp
public static class DomainRules
{
    public static decimal CalculateCharge(decimal consumption, decimal tariffPrice)
    {
        if (consumption < 0) throw new ArgumentOutOfRangeException(nameof(consumption));
        return Math.Round(consumption * tariffPrice, 2, MidpointRounding.AwayFromZero);
    }

    public static decimal CalculatePenalty(decimal debt, int daysDelayed, decimal keyRate = 0.16m)
    {
        if (daysDelayed <= 30 || debt <= 0) return 0m;
        decimal dailyRate = keyRate / 300m;
        return Math.Round(debt * dailyRate * (daysDelayed - 30), 2, MidpointRounding.AwayFromZero);
    }

    public static bool DetectAnomaly(decimal currentVolume, decimal average3MonthsVolume)
    {
        if (average3MonthsVolume <= 0) return false;
        decimal delta = currentVolume - average3MonthsVolume;
        return (delta / average3MonthsVolume > 0.30m) && (delta >= 5.0m);
    }

    public static void ValidateReading(decimal currentReading, decimal previousReading)
    {
        if (currentReading < previousReading)
            throw new InvalidOperationException("Текущие показания не могут быть меньше предыдущих показаний!");
        if ((currentReading - previousReading) > 1000m)
            throw new InvalidOperationException("Зафиксирован аномально высокий месячный расход (>1000 м³). Требуется контрольная поверка.");
    }
}
```
